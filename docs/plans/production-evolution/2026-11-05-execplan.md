## Idempotence and Recovery

S1 repeats are stable only within a splitter profile; failed embedding batches leave the prior database snapshot intact. It does not prevent duplicate provider billing after a crash, offer per-document concurrent writes or durable partial progress. S2/S3 add stage manifests, job uniqueness, an outbox, lease fencing and idempotent promotion; action idempotency later also needs downstream deduplication.

## Surprises & Discoveries

- Baseline already committed by the user. Preserve it and unrelated IDE files; do not reset the checkout.
- `Store.replace_corpus()` globally deletes chunks. It is unsuitable as a multi-tenant ingestion API; document the replacement prerequisite before deploying workers.
- Existing `chunk_tokens` actually counted UTF-8 bytes, not model tokens. Correct units explicitly during splitter migration.
- Docker and PostgreSQL binaries are absent from this environment. Do not claim distributed integration results from in-process fakes.
- Inspected installed splitter 1.1.3: its start-index bookkeeping uses character lengths. S1 consistently uses characters rather than pairing token/byte overlap with character offsets.
- New behavior tests exposed empty-snapshot deletion and a Pydantic alias configuration pitfall; rejecting empty ingestion and enabling field-name population fixed the tested failures.
- Review/failure tests caught SSE truncation after 100 events, missing terminal expiry events, revoked duplicate-source provenance and leaked resources after partial factory construction; each has a regression test and fix.
- Redacting arbitrary persistence payloads corrupts opaque object VersionIds that resemble PII. Redact source/question text before building the artifact/request; preserve opaque version identifiers exactly.
- Retry eligibility must be checked before publishing outbox events. Reconciliation must also redispatch accepted work lost before a worker claims it, not only recover expired running leases.
- Pin the complete splitter/batch/embedding profile to a job. Reusing batch ordinals after a profile change is unsafe; reject incompatible replay and submit a deliberate new generation.
- A local seed command originally reported executed IDs even when a persisted job failed. A failing regression test led to checking terminal status and failing the command honestly.
- Final review identified incomplete vendor error classification. Known vendor 408/429/5xx, S3 throttling/connection errors and transient database SQLSTATEs now use bounded job retries; authorization/schema/domain failures remain terminal. Tests cover both classification and actual job state transitions.
- Redis was removed from current dependencies because no Redis-backed cache/global limiter is implemented yet; add it with that milestone rather than implying a dependency provides the control.
- Documentation audit found architecture/low-level design still describing v1 while the README led into legacy commands. Those pages now describe actual v2 flow/state/tables; v1 setup lives in `docs/guides/legacy-v1.md`. The target design now separates actual tables and capabilities from future controls.
